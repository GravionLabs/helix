# /github-release

## Usage

```
/github-release cut [--feature <nr>]
/github-release finish [major] [release/next|release/<x.y>]
/github-release help
```

Cuts the rolling `release/next` branch, or finishes it with the release PR into the default branch.

## Arguments and flags

- `cut`: creates `release/next` from the default branch when absent, moves it to the default branch by a fast-forward after a release (never deleted), reports stale `release/<x.y>` lines; offers the `release-branch.yml` caller workflow when the repo has none.
- `--feature <nr>`: with `cut`, records `Release branch: release/next` as the second line of that Feature issue.
- `finish`: opens (or reports) the release PR with `github-pull-request` in release mode; once merged, a later `finish` moves `release/next` to the default branch by a fast-forward (it is never deleted).
- Milestone hint: once the release PR is merged and tagged `v<x.y.z>`, the later `finish` points to `/github-milestone close M<nnn>` (version from the tag, the title becomes `M<nnn> (x.y.z)`) and `/github-milestone create` for the next `M<nnn+1>`; with open issues left, `create` first, then `close M<nnn> --move-to M<nnn+1>`. Legacy repositories with an open `x.y.z` milestone get `/github-milestone close <x.y.z> [--move-to <next>]` and `create` of the next `x.y.z`.
- `--yes`: with `finish` after the merge, closes the milestone without asking: version check (`pwsh scripts/Test-ReleaseVersion.ps1 -Tag v<x.y.z>`, a mismatch stops), create the next `M<nnn+1>`, close unclosed PBIs with "Released in v<x.y.z>", `close --move-to`. Without it one confirmation lists the moved issues. Steps: `references/close-milestone.md`.
- `major`: with `finish`, adds one empty commit with `+semver: major` (not again when one exists).
- `release/next` or `release/<x.y>`: the branch to finish; default is the current release branch, else `release/next` on origin.
- Read-only state checks, JSON on stdout: `pwsh scripts/Get-ReleaseState.ps1 -Mode cut|finish|base [-Branch <b>] [-Issue <nr>]`. `cut` and `finish` report `state`, `openPrs`, `action` (`stop: ...` means change nothing); `base` resolves the base branch of a pull request.
- Version bump: no commit by default. GitVersion derives it from Conventional Commits: `fix:` patch, `feat:` minor (a `+semver: minor` commit message is GitVersion's directive for the same bump; the skill itself only ever adds `+semver: major`), `!:` or `BREAKING CHANGE:` major.
- RC test: `finish` with an open `release-test` issue in the milestone (`-Milestone <name>`) adds `RC test open: <issue URL>` to the release PR body and warns; with `release.test.gate: true` in `.agents/config.json` it refuses until the issue is closed.
- Human gate: the release PR is never merged by the skill. You merge it with a merge commit (`gh pr merge <nr> --merge`, never squash); the push to `main` builds, tags and closes the delivered issues.
- Changelog: git-cliff, generated by the release job on `main`, never edited by the skill. A repo without `cliff.toml` gets none; setup in `references/cliff-setup.md`.

## Examples

- `/github-release cut`
- `/github-release cut --feature 42`
- `/github-release finish`
- `/github-release finish major`
- `/github-release finish release/1.4`
